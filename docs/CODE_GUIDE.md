# Как устроен код — подробный разбор

Документ объясняет **каждый модуль и каждую функцию** простыми словами.
Читать сверху вниз: сначала общая идея, потом файлы по слоям MVC.

---

## 0. Общая идея и поток данных

Игра построена по паттерну **MVC**:

- **Model** (`src/models/`) — «мозг» игры: вся логика и математика. Не знает про графику и pygame.
- **View** (`src/views/`) — «глаза»: рисует то, что есть в модели, и загружает картинки/звук.
- **Controller** (`src/controllers/`) — «руки»: запускает игровой цикл, читает клавиши, командует моделью и просит View нарисовать кадр.

Поток одного кадра (60 раз в секунду):

```
клавиши → Controller → Model.update(dt) → новое состояние → View.render(model) → картинка на экране
```

### Система координат
Важно: ось **Y направлена вниз** (как принято в экранной графике).
- `y` больше → ниже на экране.
- Прыжок вверх — это **уменьшение** `y`, поэтому скорость прыжка отрицательная (`JUMP_VELOCITY = -900`).
- Гравитёра тянет вниз → увеличивает `vy` (скорость по Y).

### Что такое `dt`
`dt` (delta time) — сколько секунд прошло с прошлого кадра (примерно `1/60 ≈ 0.016`).
Мы умножаем все движения на `dt`, чтобы игра шла **с одинаковой скоростью при любом FPS**.

## 1. `src/config/constants.py` — настройки

Здесь собраны **все числа** игры (размер окна, гравитация, цвета, имена файлов).
Зачем: правило «никаких магических чисел». Если нужно изменить баланс — меняешь
одно значение здесь, а не ищешь его по всему коду (принципы DRY и чистого кода).

Ключевые группы:
- Окно: `SCREEN_WIDTH`, `SCREEN_HEIGHT`, `FPS`.
- Физика: `GRAVITY`, `JUMP_VELOCITY`, `SPRING_JUMP_VELOCITY`, `MOVE_SPEED`.
- Платформы: размеры и зазоры (`PLATFORM_MIN_GAP_Y`, `PLATFORM_MAX_GAP_RATIO`).
- Камера/счёт: `CAMERA_FOLLOW_RATIO`, `SCORE_DIVISOR`, `SPAWN_AHEAD`, `CULL_MARGIN`.
- Ассеты: имена файлов `IMAGE_PLAYER`, `IMAGE_BACKGROUND`, `BACKGROUND_PARALLAX`.
- Цвета: `COLOR_*`.

## 2. `src/models/entities.py` — игровые объекты

Это «кирпичики» мира как **чистые данные** (без pygame).

### `class PlatformKind(Enum)`
Перечисление типов платформ: `STATIC`, `MOVING`, `BREAKABLE`, `SPRING`.
Enum используем вместо строк, чтобы не было опечаток и было понятнее.

### `class _AxisAlignedBox`
Вспомогательный класс-«примесь» (mixin). Даёт любому объекту с полями
`x, y, width, height` удобные свойства прямоугольника:
- `left`, `right`, `top`, `bottom` — края.
- `center_x` — центр по горизонтали.
- `overlaps_x(other)` — пересекаются ли два объекта по горизонтали (нужно для коллизий).

Зачем отдельный класс: и игрок, и платформа — прямоугольники, логика общая →
выносим её один раз (DRY) и наследуем.

### `class Player`
`@dataclass` с полями: позиция `x, y`, скорость `vx, vy`, размеры `width, height`.
`dataclass` автоматически создаёт конструктор — меньше шаблонного кода.

### `class Platform`
Поля: `x, y`, тип `kind`, скорость `vx` (для движущихся), флаг `alive`, размеры.
Методы:
- `bounce_velocity()` — с какой силой оттолкнётся игрок. Для пружины — сильнее
  (`SPRING_JUMP_VELOCITY`), иначе обычный `JUMP_VELOCITY`.
- `on_landed()` — что происходит с платформой, когда на неё встали. Ломающаяся
  (`BREAKABLE`) помечается `alive = False` и потом удаляется.

## 3. `src/models/physics.py` — физика

Чистые функции (вход → выход), их легко тестировать.

### `max_jump_height(jump_velocity, gravity)`
Считает, на **какую высоту** подпрыгнет игрок: формула `v² / (2·g)`.
Это нужно генератору уровня, чтобы не ставить платформы выше, чем можно допрыгнуть.

### `integrate(player, dt, gravity)`
Двигает игрока за один кадр (метод **полу-неявного Эйлера**):
1. `vy += g·dt` — гравитация ускоряет падение.
2. `x += vx·dt`, `y += vy·dt` — обновляем позицию.
Благодаря `dt` скорость не зависит от FPS.

### `wrap_horizontal(player, screen_width)`
«Телепорт» через край: ушёл за левый край — появился справа, и наоборот.
Это и есть алгоритм wrap-around.

### `try_land(player, platform, prev_bottom)`
**Односторонняя коллизия** — самая важная функция платформера. Логика:
- Приземляемся только если **падаем** (`vy > 0`) и платформа `alive`.
- Проверяем, что низ игрока «пересёк» верх платформы именно в этом кадре:
  раньше был выше (`prev_bottom <= platform.top`), а теперь ниже
  (`platform.top <= player.bottom`).
- И есть пересечение по горизонтали (`overlaps_x`).

Если всё так — ставим игрока ровно на платформу, задаём прыжковую скорость вверх
и вызываем `platform.on_landed()`. Возвращаем `True` (приземлились).

Почему «прошлый низ»: без него игрок «прилипал» бы к платформе и при прыжке снизу
вверх. Мы пропускаем платформу, когда летим вверх, и ловим только при падении.

## 4. `src/models/level_generator.py` — генерация уровня

### `class LevelGenerator`
Создаёт платформы по мере подъёма. Принимает `rng` (генератор случайных чисел) —
его можно зафиксировать в тестах, чтобы результат был предсказуем.

- `__init__` — считает `_max_gap_y`: максимальный безопасный вертикальный зазор
  = высота прыжка × `PLATFORM_MAX_GAP_RATIO`. Это гарантия **проходимости**.
- `random_x()` — случайная позиция по X в пределах экрана.
- `_pick_kind(height_climbed)` — выбирает тип платформы. Чем выше залез игрок,
  тем чаще попадаются сложные типы (движущиеся, ломающиеся). Это масштабирование
  сложности.
- `next_platform(highest_y, height_climbed)` — создаёт одну платформу выше самой
  верхней: берёт случайный зазор в диапазоне `[MIN_GAP, max_gap_y]` (всегда
  допрыгиваемо), задаёт тип и, если движущаяся, начальную скорость.
- `initial_platforms(start_y, count)` — стартовый набор: одна платформа прямо под
  игроком + `count` платформ выше, все простые и достижимые.

## 5. `src/models/game_model.py` — главная модель

`class GameModel` связывает всё вместе и хранит состояние партии.

Поля: `player`, список `platforms`, `camera_y` (где сейчас «камера»), `score`,
`is_game_over`, `_start_y` (стартовая высота — от неё считаем очки).

### `reset()`
Начинает новую партию: ставит игрока по центру внизу, даёт ему стартовый прыжок,
генерирует платформы, обнуляет счёт и флаги.

### `update(dt, move_dir)` — главный метод, вызывается каждый кадр
`move_dir` это `-1` (влево), `0` (стоп) или `+1` (вправо). По шагам:
1. Задаёт горизонтальную скорость: `vx = move_dir × MOVE_SPEED`.
2. Запоминает `prev_bottom` (низ игрока до движения — нужен для коллизии).
3. `physics.integrate` — двигает игрока (гравитация + скорость).
4. `physics.wrap_horizontal` — телепорт через край.
5. Уменьшает таймер перезарядки оружия (`fire_cooldown_remaining`).
6. `_update_moving_platforms` — двигает движущиеся платформы.
7. `_resolve_landings` — проверяет приземления.
8. `_collect_items` — подбор предметов (монеты/элитры/оружие).
9. `_update_projectiles` — двигает снаряды игрока и стрелы врагов, убирает улетевшие.
10. `_update_enemies` — обновляет поведение врагов.
11. `_hit_enemies_with_projectiles` — попадания снарядов игрока по врагам.
12. `_follow_camera` — поднимает камеру за игроком.
13. `_update_score` — обновляет счёт.
14. `_recycle_objects` — удаляет нижние объекты, досоздаёт верхние (+ враги/оружие).
15. `_check_portals` / `_check_enemy_contact` — гибель от портала, врага или его стрелы.
16. `_check_game_over` — проверяет падение.

### `_update_moving_platforms(dt)`
Двигает платформы типа `MOVING` влево-вправо. У края меняет направление
(`vx = -vx`) — получается «маятник».

### `_resolve_landings(prev_bottom)`
Перебирает платформы и вызывает `try_land`. Как только нашли одну, на которую
встали — выходим (`break`), чтобы не приземлиться сразу на несколько.

### `_follow_camera()`
Камера следует за игроком, **только когда он поднимается** выше определённой линии
(`CAMERA_FOLLOW_RATIO` = 40% от верха). Вниз камера не опускается — классика жанра.

### `_update_score()`
Счёт = максимальная пройденная высота: `(стартовый Y − текущий Y) / SCORE_DIVISOR`.
`max(...)` — чтобы счёт не уменьшался, когда игрок проседает вниз.

### `_recycle_objects()`
1. Удаляет платформы, предметы, порталы и врагов, которые `alive == False`
   или ушли ниже экрана (culling — экономит память и время).
2. Вызывает `_spawn_above()` — досоздаёт платформы (+ предметы, оружие, врагов) сверху.

### `_spawn_above()`
Пока самая верхняя платформа не достигла «потолка спавна» (`camera_y − SPAWN_AHEAD`),
создаёт новые через `generator.next_platform`. Так мир всегда «бесконечный».

### `_check_game_over()`
Если верх игрока опустился ниже нижней границы экрана — игрок упал → `is_game_over = True`.

## 6. `src/views/assets.py` — загрузка ресурсов

`class AssetManager` — единственное место, где грузятся картинки/звук/шрифты.

- `image(name, size, smooth)` — грузит картинку из `assets/images/` и кэширует.
  `smooth=False` = пиксельное масштабирование (для стиля Minecraft, без размытия).
  Если файла нет — возвращает серый плейсхолдер, и игра не падает.
- `sound(name)` — грузит звук; если нет файла или звук недоступен — возвращает `None`.
- `play_music(name, volume, loop)` — включает фоновую музыку из `assets/sounds/`
  по кругу (`loop=True`). Если файла нет — тихо ничего не делает.
- `font(size, bold)` — системный шрифт с поддержкой кириллицы (кэшируется по размеру и жирности).
- `set_volume(volume)` — общая громкость всех звуков.
- `_make_placeholder` — рисует заглушку, когда картинки нет.

## 7. `src/views/game_view.py` — отрисовка игры

`class GameView` рисует один кадр. В конструкторе (`_load_sprites`) заранее готовит
все спрайты: две позы игрока (стойка/прыжок) и их отражённые версии, спрайты
платформ по типам, тайлы неба и земли.

- `render(model)` — порядок: небо → земля → платформы → игрок → счёт.
- `_draw_sky(camera_y)` — заливает фон и **замощает** его тайлом неба. Смещение
  зависит от `camera_y × BACKGROUND_PARALLAX` → небо плавно «едет» (параллакс).
- `_draw_ground(camera_y)` — рисует землю тайлами у низа. Земля зафиксирована в
  мире (`GROUND_TOP_Y`); при подъёме `screen_top = GROUND_TOP_Y − camera_y` растёт,
  и земля уезжает вниз за экран (тогда метод просто ничего не рисует).
- `_draw_platform(platform, camera_y)` — рисует спрайт по типу платформы.
  Экранный Y = `world_y − camera_y` (мировые координаты → экранные).
- `_draw_player(model)` — выбирает позу: `vy < 0` (летит вверх) → прыжок, иначе
  стойка; при движении влево берёт отражённый спрайт (`_facing_left`).
- `_select_player_sprite(rising)` — возвращает нужный из 4 вариантов
  (прыжок/стойка × вправо/влево).
- `_draw_hud(model)` — выводит счёт.

## 9. `src/controllers/game_controller.py` — управление

`class SceneState(Enum)` — в какой «сцене» мы сейчас: `MAIN_MENU`, `PLAYING`,
`PAUSED`, `GAME_OVER`. От сцены зависит, что обновлять и рисовать.

`class GameController`:
- `__init__` — инициализирует pygame, окно, загружает рекорд/громкость, создаёт
  модель и View.
- `run()` — **главный цикл**: посчитать `dt` → обработать события → обновить →
  нарисовать → показать кадр. Повторять, пока игра не закрыта.
- `_handle_events()` — читает события (закрытие окна, нажатия клавиш).
- `_handle_keydown(key)` — раздаёт нажатие нужному обработчику в зависимости от сцены
  (словарь `handlers` вместо длинного `if`).
- `_keys_*` — что делают клавиши в каждой сцене (Enter — играть, Esc — пауза/выход).
- `_read_move_direction()` — смотрит, зажаты ли стрелки/`A`/`D`, и возвращает `-1/0/+1`.
  Используем «зажатие» (а не разовое нажатие), чтобы движение было плавным.
- `_start_new_game()` — сбрасывает модель и переходит в игру.
- `_update(dt)` — если идёт игра, двигает модель и проверяет проигрыш.
- `_on_game_over()` — сохраняет рекорд (если побит) и переключает сцену.
- `_render()` — рисует нужную сцену (меню/игра/пауза/проигрыш).

## 10. `src/services/save_service.py` — сохранения

`class SaveService` хранит рекорд и громкость в JSON-файле.
- `load_best_score()` / `save_best_score(score)` — рекорд (сохраняется, только если
  новый больше).
- `load_volume(default)` / `save_volume(volume)` — громкость.
- `_read()` / `_write()` — чтение/запись JSON; при ошибке/отсутствии файла
  возвращает пустой словарь (не падает).

## 13. Как добавить свою графику (стиль Minecraft)

Подробнее — в `docs/ASSETS.md`. Кратко:
1. Положи PNG персонажа в `assets/images/player.png`.
2. Положи текстуру фона (например, камень/земля) в `assets/images/background.png`.
3. Запусти игру — спрайты подхватятся автоматически (имена заданы в `constants.py`).

Картинки масштабируются «по-пиксельному» (`smooth=False`), поэтому пиксель-арт
останется чётким, как в Minecraft.

## 14. Предметы и опасности: монеты, элитры, портал

### Иерархия классов (в `entities.py`)
- `Collectible` — **абстрактный** базовый класс предмета. У него есть метод
  `apply(model)`, который каждый предмет реализует по-своему (полиморфизм — важно
  для критерия ООП).
- `Coin(Collectible)` — монета. `apply` вызывает `model.add_coin()`.
- `Elytra(Collectible)` — редкий предмет. `apply` вызывает `model.start_flight()`.
- `Portal` — не предмет, а **опасная зона**: отдельный прямоугольник у края экрана.

`overlaps(other)` — полная проверка пересечения двух прямоугольников (по X и по Y),
используется и для сбора предметов, и для столкновения с порталом.

### Генерация (в `level_generator.py`)
- `maybe_item(platform)` — с некоторой вероятностью кладёт на платформу монету
  (часто) или элитры (редко); иначе ничего.
- `maybe_portal(near_y)` — с небольшой вероятностью ставит портал у левого или
  правого края на заданной высоте.

### Логика в модели (`game_model.py`)
- Поля: `items` (список предметов), `portals`, `coins` (монеты за забег),
  `is_flying` + `_flight_target_y` (состояние полёта).
- `add_coin()` — увеличивает счётчик монет.
- `start_flight()` — включает полёт и запоминает целевую высоту
  (`текущая_y − ELYTRA_BOOST_HEIGHT`).
- `_fly(dt)` — пока летим: держим постоянную скорость вверх, без гравитации; как
  только достигли цели — выключаем полёт (дальше работает обычная физика).
- `_collect_items()` — если игрок пересёкся с предметом, вызывает `item.apply(self)`
  и помечает предмет собранным.
- `_check_portals()` — если игрок коснулся портала → `is_game_over = True`.
- Спавн предметов/порталов происходит в `_spawn_above()` вместе с платформами,
  очистка — в `_recycle_objects()`.

### Сохранение монет (`save_service.py`)
- `add_coins(amount)` — прибавляет монеты забега к общему счёту в JSON
  (`total_coins`), `load_total_coins()` — читает. Контроллер сохраняет монеты при
  проигрыше; меню показывает общий счёт (задел под магазин скинов).

### Отрисовка (`game_view.py`)
- Рисуются спрайты монет/элитр (`coin.png`, `elytra.png`) и портала (`portal.png`).
- HUD показывает счёт и монеты за забег.
- Небо чуть «дышит» (синусоидальный дрейф) — без швов.

## 15. Оружие и стрельба

### Типы оружия (`entities.py`)
- `WeaponKind` — перечисление: `BOW` (лук), `PISTOL` (пистолет), `RIFLE` (автомат).
  У него два «умных» свойства, чтобы данные жили рядом с типом (ООП):
  - `cooldown` — задержка между выстрелами (лук 3 с, пистолет 1 с, автомат 0.5 с);
  - `spawn_height` — высота, на которой оружие появляется (1000 / 2000 / 5000).
- `Weapon(Collectible)` — пикап оружия на платформе. `apply` вызывает
  `model.equip_weapon(kind)` — то есть подбор оружия = тот же механизм, что у монет.
- `Projectile` — снаряд: координаты, скорость `vy` (вверх), тип оружия и флаг
  `alive` (понадобится, когда снаряд начнёт попадать по врагам).

### Логика в модели (`game_model.py`)
- Поля: `current_weapon` (что в руках, `None` если ничего),
  `fire_cooldown_remaining` (сколько ждать до следующего выстрела),
  `projectiles` (список летящих снарядов), `_weapons_pending` (какие виды оружия
  ещё не заспавнены, отсортированы по высоте).
- `equip_weapon(kind)` — берём оружие; оно **остаётся в руках, пока не подберём
  другое**. Кулдаун сбрасывается, можно сразу стрелять.
- `try_shoot()` — выстрел: если оружие есть и кулдаун прошёл, создаём снаряд над
  игроком и ставим кулдаун по типу оружия. Возвращает, удалось ли выстрелить.
- В `update()`: каждый кадр уменьшаем `fire_cooldown_remaining` и двигаем снаряды
  (`_update_projectiles`) — они летят вверх и удаляются, уйдя за верх экрана.
- `_maybe_spawn_weapon(platform)` — когда новая платформа оказывается выше
  очередного порога высоты, кладём на неё следующее оружие (каждое — один раз).

### Управление (`game_controller.py`)
- Клавиша **пробел** во время игры вызывает `model.try_shoot()`.

### Отрисовка (`game_view.py`)
- Спрайт игрока зависит от текущего оружия (для каждого оружия свои позы
  стойка/прыжок; без оружия — обычный игрок).
- Рисуются пикапы оружия на платформах и летящие снаряды (стрела/пуля).
- HUD показывает текущее оружие.

### Снаряды и враги
Снаряды игрока бьют по врагам — см. раздел 16.

## 16. Враги

### Иерархия (в `entities.py`)
- `Enemy` — **абстрактный** базовый класс. Общее: координаты, `hp`, флаг `alive`,
  метод `hit()` (минус 1 HP за любой выстрел, тип оружия не важен) и абстрактный
  `update(dt, model)` (поведение). Полиморфизм — каждый враг ведёт себя по-своему.
- `Zombie(Enemy)` — HP 2, `update` ничего не делает (статичный).
- `Spider(Enemy)` — HP 1, в `update` едет по X и отскакивает от краёв экрана.
- `Skeleton(Enemy)` — HP 3, в `update` патрулирует по Y (отрезок = высоте экрана)
  и раз в секунду стреляет стрелой через `model.spawn_enemy_projectile(...)`.
  Поле `direction` задаёт сторону стрельбы (слева → вправо, справа → влево).

### Снаряды (`Projectile`)
- Один класс на оба случая: у него есть `vx` и `vy`. Снаряд игрока летит вверх
  (`vy < 0`), стрела врага — вбок (`vx ≠ 0`). Поле `weapon` выбирает спрайт
  (стрелы врага используют `arrow.png`).

### Логика в модели (`game_model.py`)
- Поля: `enemies` (живые враги), `enemy_projectiles` (их стрелы).
- `_update_enemies(dt)` — двигает/стреляет каждым врагом.
- `_hit_enemies_with_projectiles()` — попадание выстрела игрока: `enemy.hit()`,
  снаряд гаснет; при HP ≤ 0 враг убирается на этапе очистки.
- `_check_enemy_contact()` — касание врага **или** его стрелы → конец игры.
- `spawn_enemy_projectile(x, y, vx)` — создаёт горизонтальную стрелу врага.
- Спавн врагов — в `_spawn_above()` через `generator.maybe_enemy(...)`, очистка
  (мёртвые/уехавшие вниз) — в `_recycle_objects()`.

### Генерация (`level_generator.py`)
- `maybe_enemy(near_y, height_score)` — с шансами создаёт врага, но **не раньше**
  высоты `ENEMY_MIN_HEIGHT` (честный старт). Важно: `height_score` — высота
  платформы **в очках** (как на экране), а не в пикселях, чтобы порог 1000
  совпадал с высотами спавна оружия.
- `_make_skeleton(near_y)` — ставит скелета у левого/правого края, задаёт сторону
  стрельбы и границы вертикального патруля.

### Отрисовка (`game_view.py`)
- У каждого врага один спрайт (выбор по типу через словарь). Рисуются и стрелы
  врагов (теми же спрайтами снарядов).

## 17. Фоновая музыка

- Файл кладётся в `assets/sounds/music.ogg` (имя — `MUSIC_BACKGROUND` в `constants.py`,
  громкость — `MUSIC_VOLUME`). Поддерживаются `.ogg`, `.mp3`, `.wav`.
- Воспроизведение делает `AssetManager.play_music` через `pygame.mixer.music`
  с `play(-1)` — это зацикливание на всё время игры.
- Запуск музыки происходит один раз в конструкторе `GameController`. Если файла
  нет или аудио недоступно — игра просто запускается без музыки (не падает).
