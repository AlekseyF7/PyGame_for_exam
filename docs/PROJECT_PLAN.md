# «Jump or die» — план проекта и анализ под критерии

2D вертикальный платформер-«прыгун» на PyGame. Архитектура MVC, чистый ООП,
тестируемая модель. Цель — максимальный балл на экзамене.

## 1) Почему смена жанра оправдана
- Лёгкие ассеты: простые спрайты и пара коротких звуков (нет тяжёлого VHS/CRT рендера).
- При этом жанр богат на **сложные алгоритмы**: физика, процедурная генерация,
  коллизии, баллистика — это закрывает самый «дорогой» критерий (до 15 баллов).

## 2) Анализ под критерий «Сложность алгоритма» (до 15 баллов)
Формула из таблицы: Лёгкие ≤4×1 (max 4) + Средние ≤3×2 (max 6) + Сложные ≤3×4 (max 12).
Цель — **4 лёгких + 3 средних + 3 сложных = 15/15**.

### Лёгкие (×1, до 4)
1. **Wrap-around по горизонтали** — игрок, уходя за край, появляется с другой стороны (по модулю ширины).
2. **Подсчёт очков по высоте** — счёт = максимальная пройденная высота.
3. **Culling платформ** — удаление платформ, ушедших ниже экрана.
4. **Линейная регулировка громкости / настройки**.

### Средние (×2, до 3)
1. **Физика прыжка** — интегрирование гравитации (полу-неявный Эйлер), независимое от FPS (`v += g·dt`, `y += v·dt`).
2. **Односторонняя коллизия игрок–платформа** — приземление только при падении сверху (AABB + сравнение «прошлый/текущий низ»).
3. **Процедурная генерация с масштабированием сложности** — плотность и типы платформ зависят от высоты.

### Сложные (×4, до 3) — реализовано
1. **Гарантированная проходимость генерации** — по физике вычисляем максимальную высоту прыжка
   (`h = v²/2g`) и размещаем платформы только в достижимой зоне (`gap_y ≤ h_max`).
2. **ИИ врагов (полиморфные поведения)** — статичный зомби, паук по горизонтали,
   скелет по вертикали с периодической направленной стрельбой; общий метод `update`.
3. **Боевые столкновения** — снаряды игрока ↔ враги (с HP), контакт/стрелы врагов ↔ игрок
   (широкая фаза перебором пар с проверкой AABB).

## 3) Механики и фичи (для «полноценности проекта» и ООП-иерархий)
- **Типы платформ** (по `PlatformKind`): статичная, движущаяся, ломающаяся, пружина.
- **Предметы** (иерархия `Collectible`): монеты (счёт + сохранение), элитры (рывок вверх).
- **Опасности**: порталы у краёв — мгновенная гибель при касании.
- **Оружие** (`WeaponKind` + пикапы `Weapon`): лук, пистолет, автомат; стрельба снарядами.
- **Враги** (иерархия `Enemy`): зомби, паук, скелет; убиваются выстрелами (HP).
- **UI**: главное меню, пауза, экран Game Over, HUD (счёт / монеты / оружие).
- **Звук**: зацикленная фоновая музыка.
- **Сохранение**: рекорд и накопленные монеты в JSON.

## 4) Подходит ли игра для максимального балла?
**Да.** Покрытие критериев:
- *Сложность алгоритмов*: достижимо 15/15 (см. раздел 2).
- *ООП*: инкапсуляция (состояние в моделях), наследование (Platform/PowerUp/Enemy),
  абстракция (базовые классы + интерфейс `update`).
- *MVC / архитектура*: модель без pygame, view — рендер, controller — цикл и ввод.
- *SOLID/DRY/KISS*: константы вместо магических чисел, разнесение ответственности.
- *Тестирование*: физика и генерация — чистая логика, легко покрывается `unittest`.
- *Полноценность*: меню, сохранения, рекорды, рабочий билд, git-история.

Риск только один — не «раздуть» лишним. Сложные алгоритмы берём осознанно, по одному.

## 5) Структура проекта
```text
src/
  main.py
  config/constants.py
  models/
    entities.py         # Player, Platform, Collectible/Coin/Elytra/Weapon,
                        # Portal, Projectile, Enemy/Zombie/Spider/Skeleton (без pygame)
    physics.py          # гравитация, коллизии, wrap-around
    level_generator.py  # процедурная генерация платформ, предметов, врагов
    game_model.py       # общее состояние, счёт, бой, game over
  views/
    assets.py           # загрузка спрайтов/звуков/шрифтов, музыка
    game_view.py        # рендер игрового мира + HUD
    menu_view.py        # меню, пауза, game over
  controllers/
    game_controller.py  # игровой цикл, ввод, сцены
  services/
    save_service.py     # рекорд/монеты/настройки (JSON)
tests/                  # 43 теста
  test_physics.py
  test_level_generator.py
  test_game_model.py
  test_items.py
  test_weapons.py
  test_enemies.py
```

## 6) Этапы
- **A (готово):** играбельная база — гравитация, прыжок по платформам, камера, счёт, генерация, game over.
- **B (готово):** типы платформ + меню/пауза/game over + сохранение.
- **C (готово):** предметы (монеты, элитры), порталы, враги (ООП-иерархия).
- **D (готово):** оружие и стрельба снарядами.
- **E (готово):** баланс, фоновая музыка, 43 теста на все алгоритмы.
- **Дальше:** магазин скинов за монеты, финиш уровня на высоте 10000, доп. звуки.
