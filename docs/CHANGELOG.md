# Журнал изменений

Здесь фиксируются все изменения проекта (что и зачем сделано).

## [Баланс: размеры, скорострельность, фикс высоты спавна]
- **Размеры увеличены**: игрок 46→**56**, враги 48→**64** (`PLAYER_WIDTH/HEIGHT`,
  `ENEMY_SIZE`).
- **Скелет стреляет реже** — раз в **2 секунды** (`SKELETON_SHOOT_COOLDOWN`).
- **Исправлен баг**: враги появлялись раньше высоты 1000. Причина — порог
  `ENEMY_MIN_HEIGHT` сравнивался с высотой в **пикселях**, а не в очках
  (`SCORE_DIVISOR = 10`, поэтому 1000 px = всего 100 очков). Теперь
  `maybe_enemy` получает высоту платформы **в очках** — так же, как считается
  спавн оружия, и враги действительно стартуют с 1000.

## [Баланс врагов]
- Враги начинают появляться **с высоты 1000** (как и оружие) — `ENEMY_MIN_HEIGHT = 1000`.
- Частоты спавна на платформу: **зомби — 10%** (чаще всего), **паук — 5%**
  (реже), **скелет — 2%** (редко). Суммарно ~17% на платформу: враги попадаются
  регулярно, но не на каждом шаге.

## [Враги + читаемое меню]

### Меню
- Текст меню теперь **жирный, оттенками белого** и с тёмной тенью
  (`COLOR_MENU_*`), чтобы не сливался с фоном-картинкой. У `AssetManager.font`
  добавлен параметр `bold`.

### Враги (общая механика)
- Любой враг **убивает игрока сразу** при контакте; снаряды врагов — тоже с
  одного попадания. У каждого врага есть **HP** (число попаданий из оружия
  игрока, тип оружия не важен — каждый выстрел снимает 1 HP).
- Базовый класс `Enemy` (абстрактный, метод `update(dt, model)` и `hit()`),
  наследники реализуют поведение — полиморфизм (важно для критерия ООП).
- У каждого врага **по одному спрайту** (внешне не меняются):
  `zombie.png`, `spider.png`, `skeleton.png`.

### Типы врагов
- **Зомби** (`Zombie`) — спавнится где угодно (в т.ч. на платформе),
  **статичный**, HP = 2.
- **Паук** (`Spider`) — спавнится где угодно, **двигается по горизонтали** и
  отскакивает от краёв (как движущаяся платформа), HP = 1.
- **Скелет** (`Skeleton`) — спавнится **только у левого/правого края**,
  **двигается по вертикали** (длина патруля = высоте экрана), HP = 3.
  **Стреляет стрелами** (`arrow.png`) раз в 1 с: слева — вправо, справа — влево.

### Снаряды врагов
- `Projectile` получил поле `vx` — теперь снаряды летят и вверх (игрок), и вбок
  (враги). Список `enemy_projectiles` в модели; стрелы врагов убивают игрока.
- Снаряды игрока бьют по врагам (`_hit_enemies_with_projectiles`), снимая 1 HP.

### Где реализовано
- `constants.py` — HP, скорости, шансы спавна, `ENEMY_MIN_HEIGHT`, имена картинок.
- `entities.py` — `Enemy/Zombie/Spider/Skeleton`, `Projectile.vx`, `center_y`.
- `game_model.py` — списки `enemies`/`enemy_projectiles`, движение, урон,
  столкновения (`_update_enemies`, `_hit_enemies_with_projectiles`,
  `_check_enemy_contact`, `spawn_enemy_projectile`), спавн в `_spawn_above`.
- `level_generator.py` — `maybe_enemy` (с порогом высоты) и `_make_skeleton`.
- `game_view.py` — спрайты врагов и их снарядов.
- `tests/test_enemies.py` — 12 тестов (HP, движение, стрельба, урон, спавн).

## [Оружие и стрельба]

### Механика оружия
- Три типа оружия (`WeaponKind`): **лук**, **пистолет**, **автомат**.
- Спавнится по одному разу каждое — лук на высоте 1000, пистолет на 2000,
  автомат на 5000 (`WEAPON_HEIGHT_*`). Оружие кладётся на платформу как предмет
  `Weapon(Collectible)`; при касании игрок его подбирает (`equip_weapon`).
- Подобранное оружие **остаётся в руках, пока его не заменит другое**
  (поле `current_weapon` в модели; меняется при подборе нового).

### Механика стрельбы
- Выстрел по **пробелу** (`game_controller._keys_playing` → `model.try_shoot`).
- Снаряд (`Projectile`) летит **строго вверх** над игроком и удаляется, уйдя
  за верх экрана (`PROJECTILE_SPEED`, `_update_projectiles`).
- **Перезарядка** у каждого оружия своя: лук — 3 с, пистолет — 1 с, автомат —
  0.5 с (`BOW/PISTOL/RIFLE_COOLDOWN`, свойство `WeaponKind.cooldown`). Между
  выстрелами действует кулдаун `fire_cooldown_remaining`.
- Снаряды пока ни с чем не сталкиваются — взаимодействие с врагами добавим
  на следующем шаге (поле `Projectile.alive` уже готово под это).

### Изображения (задел)
- Заведены имена файлов под спрайты: пикапы оружия (`IMAGE_WEAPON_*`),
  снаряды/патроны (`IMAGE_PROJECTILE_*`: стрела/пуля), модельки игрока с оружием
  в позах «стоит/прыжок» (`IMAGE_PLAYER_BOW/PISTOL/RIFLE[_JUMP]`).
- `GameView` уже грузит и рисует их (пока с плейсхолдерами, если файла нет):
  пикапы на платформах, снаряды, спрайт игрока зависит от текущего оружия.
- В HUD добавлена строка «Оружие: …».

### Где реализовано
- `constants.py` — высоты спавна, перезарядки, размеры/скорость снаряда, имена картинок.
- `entities.py` — `WeaponKind` (с `cooldown`/`spawn_height`), `Weapon`, `Projectile`.
- `game_model.py` — `equip_weapon`, `try_shoot`, `_update_projectiles`,
  `_maybe_spawn_weapon` (разовый спавн по высоте), кулдаун в `update`.
- `game_controller.py` — пробел → выстрел.
- `game_view.py` — спрайты оружия/снарядов/игрока с оружием, HUD.
- `tests/test_weapons.py` — 9 тестов (подбор, замена, кулдаун, полёт снаряда, спавн).

## [beta-1: предметы, портал, переименование, фон меню, движение неба]

### Переименование
- Игра теперь **«Jump or die»** (`WINDOW_TITLE`, заголовок меню).

### Лёгкое движение неба (без швов)
- Небо масштабируется чуть выше экрана и плавно «дышит» по синусоиде
  (`SKY_DRIFT`, `SKY_DRIFT_FREQ`) — швов нет, есть мягкое движение.

### Фон главного меню
- Добавлена картинка меню `assets/images/menu_bg.png` (`IMAGE_MENU_BACKGROUND`),
  рисуется на весь экран в `MenuView.render_main_menu`.

### Новые игровые объекты (ООП-иерархия)
- Базовый класс `Collectible` (абстрактный, метод `apply(model)`), наследники:
  - **`Coin`** — монета: спавнится на платформах (~25%), при сборе `coins += 1`.
    Монеты за забег суммируются и сохраняются в JSON (`SaveService.add_coins`,
    `total_coins`), выводятся в HUD и в меню. Задел под будущий магазин скинов.
  - **`Elytra`** — редкий предмет (~4%): при подборе включает **полёт вверх**
    на `ELYTRA_BOOST_HEIGHT` пикселей (аналог ракетного ранца).
- **`Portal`** — опасная зона у края экрана (~6%): при касании игрок погибает.
  Стоит сбоку, мешает, но не перекрывает путь полностью.

### Где реализовано
- `entities.py` — классы `Collectible/Coin/Elytra/Portal`, полная AABB-проверка
  `overlaps`.
- `level_generator.py` — `maybe_item`, `maybe_portal`.
- `game_model.py` — поля `items`, `portals`, `coins`, состояние полёта; методы
  `add_coin`, `start_flight`, `_fly`, `_collect_items`, `_check_portals`; спавн в
  `_spawn_above`, очистка в `_recycle_objects`.
- `game_view.py` — отрисовка предметов/портала, HUD с монетами, дрейф неба.
- `save_service.py` — `load_total_coins`, `add_coins`.

### Новые ассеты (положить в `assets/images/`)
`menu_bg.png`, `coin.png`, `elytra.png`, `portal.png`. Нет файла → плейсхолдер.

### Проверки
- 21 unittest проходит (добавлен `tests/test_items.py`: сбор монеты, полёт элитр,
  смерть от портала, спавн предметов/порталов).
- Headless-рендер всех сцен и объектов без ошибок.

## [Фикс отображения фона, земли и платформ]

Проблемы по скриншоту: швы на небе, искажённая земля, платформы-«заглушки».

### Причины и исправления
- **Платформы серые (плейсхолдеры):** файл назывался `platform_static.jpg`, а код
  искал `.png`. Добавлен **фолбэк по расширению** в `AssetManager`
  (`_resolve_image_path`): если точного файла нет, ищется тот же файл с другим
  расширением (`.png/.jpg/.jpeg/.webp/.bmp`). Теперь имя в `constants.py` и реальное
  расширение могут не совпадать.
- **Швы на небе:** небо больше не тайлится квадратами. `background.png` растягивается
  **на весь экран один раз** (`_draw_sky`) — швов нет.
- **Искажённая земля:** земля масштабируется в полосу по ширине экрана **с сохранением
  пропорций** и повторяется вниз (`_scale_to_width` + `_draw_ground`).
- **Сплющенный персонаж:** спрайт игрока теперь масштабируется по ширине с сохранением
  пропорций и выравнивается низом по хитбоксу (`_draw_player`).
- **Платформы тонкие:** высота платформы увеличена `PLATFORM_HEIGHT` 16 → 20.

### Удалены неиспользуемые константы
- `BACKGROUND_PARALLAX`, `GROUND_TILE` больше не нужны (небо не тайлится, земля
  считается по пропорциям).

### Затронутые файлы
- `src/views/assets.py`, `src/views/game_view.py`, `src/config/constants.py`.
- Проверки: 14 unittest проходят; все спрайты грузятся (включая `.jpg`); рендер без ошибок.

## [Графика: анимация, земля, спрайты платформ]

### Анимация персонажа (2 кадра)
- Добавлен второй спрайт персонажа «в прыжке»: файл `assets/images/player_jump.png`
  (константа `IMAGE_PLAYER_JUMP`).
- В `GameView` загружаются обе позы (стойка/падение и прыжок) + их отражённые версии.
- `GameView._draw_player` выбирает позу по скорости: если игрок летит вверх
  (`vy < 0`) — поза прыжка, иначе — обычная. При движении влево спрайт отражается.

### Земля на старте, небо выше
- Добавлен фон-небо (`background.png`, тайл) и **земля** (`ground.png`, константа
  `IMAGE_GROUND`).
- Земля — это объект, зафиксированный в мире у нижней границы старта
  (`GROUND_TOP_Y`). Метод `GameView._draw_ground` рисует её тайлами по низу.
- При подъёме камера уходит вверх, и земля **сама уезжает вниз за экран** —
  остаётся только небо. Отдельной логики «переключения» не нужно.

### Платформы в стиле Minecraft (спрайты по типам)
- Для каждого типа платформы свой PNG:
  - `platform_static.png`, `platform_moving.png`, `platform_breakable.png`,
    `platform_spring.png` (константы `IMAGE_PLATFORM_*`).
- `GameView` хранит словарь `kind → спрайт` и рисует нужный спрайт вместо цветного
  прямоугольника. Если файла нет — показывается плейсхолдер (игра не падает).

### Технические детали
- Все картинки масштабируются «по-пиксельному» (`smooth=False`) — чёткий пиксель-арт.
- Затронутые файлы: `src/config/constants.py`, `src/views/game_view.py`,
  `docs/ASSETS.md`.
- Проверки: 14 unittest проходят; headless-рендер без ошибок; смена поз
  (прыжок/падение) подтверждена тестовым прогоном.
