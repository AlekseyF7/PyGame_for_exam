# Журнал изменений

Здесь фиксируются все изменения проекта (что и зачем сделано).

## [beta-1: предметы, портал, переименование, фон меню, движение неба]

### Переименование
- Игра теперь **«Jump or die»** (`WINDOW_TITLE`, заголовок меню).

### Лёгкое движение неба (без швов)
- Небо масштабируется чуть выше экрана и плавно «дышит» по синусоиде
  (`SKY_DRIFT`, `SKY_DRIFT_FREQ`) — швов нет, есть мягкое движение.

### Фон главного меню
- Добавлена картинка меню `assets/images/menu_bg.png` (`IMAGE_MENU_BACKGROUND`),
  рисуется на весь экран в `MenuView.render_main_menu`.

### Новые игровые объекты (ООП-иерархия)
- Базовый класс `Collectible` (абстрактный, метод `apply(model)`), наследники:
  - **`Coin`** — монета: спавнится на платформах (~25%), при сборе `coins += 1`.
    Монеты за забег суммируются и сохраняются в JSON (`SaveService.add_coins`,
    `total_coins`), выводятся в HUD и в меню. Задел под будущий магазин скинов.
  - **`Elytra`** — редкий предмет (~4%): при подборе включает **полёт вверх**
    на `ELYTRA_BOOST_HEIGHT` пикселей (аналог ракетного ранца).
- **`Portal`** — опасная зона у края экрана (~6%): при касании игрок погибает.
  Стоит сбоку, мешает, но не перекрывает путь полностью.

### Где реализовано
- `entities.py` — классы `Collectible/Coin/Elytra/Portal`, полная AABB-проверка
  `overlaps`.
- `level_generator.py` — `maybe_item`, `maybe_portal`.
- `game_model.py` — поля `items`, `portals`, `coins`, состояние полёта; методы
  `add_coin`, `start_flight`, `_fly`, `_collect_items`, `_check_portals`; спавн в
  `_spawn_above`, очистка в `_recycle_objects`.
- `game_view.py` — отрисовка предметов/портала, HUD с монетами, дрейф неба.
- `save_service.py` — `load_total_coins`, `add_coins`.

### Новые ассеты (положить в `assets/images/`)
`menu_bg.png`, `coin.png`, `elytra.png`, `portal.png`. Нет файла → плейсхолдер.

### Проверки
- 21 unittest проходит (добавлен `tests/test_items.py`: сбор монеты, полёт элитр,
  смерть от портала, спавн предметов/порталов).
- Headless-рендер всех сцен и объектов без ошибок.

## [Фикс отображения фона, земли и платформ]

Проблемы по скриншоту: швы на небе, искажённая земля, платформы-«заглушки».

### Причины и исправления
- **Платформы серые (плейсхолдеры):** файл назывался `platform_static.jpg`, а код
  искал `.png`. Добавлен **фолбэк по расширению** в `AssetManager`
  (`_resolve_image_path`): если точного файла нет, ищется тот же файл с другим
  расширением (`.png/.jpg/.jpeg/.webp/.bmp`). Теперь имя в `constants.py` и реальное
  расширение могут не совпадать.
- **Швы на небе:** небо больше не тайлится квадратами. `background.png` растягивается
  **на весь экран один раз** (`_draw_sky`) — швов нет.
- **Искажённая земля:** земля масштабируется в полосу по ширине экрана **с сохранением
  пропорций** и повторяется вниз (`_scale_to_width` + `_draw_ground`).
- **Сплющенный персонаж:** спрайт игрока теперь масштабируется по ширине с сохранением
  пропорций и выравнивается низом по хитбоксу (`_draw_player`).
- **Платформы тонкие:** высота платформы увеличена `PLATFORM_HEIGHT` 16 → 20.

### Удалены неиспользуемые константы
- `BACKGROUND_PARALLAX`, `GROUND_TILE` больше не нужны (небо не тайлится, земля
  считается по пропорциям).

### Затронутые файлы
- `src/views/assets.py`, `src/views/game_view.py`, `src/config/constants.py`.
- Проверки: 14 unittest проходят; все спрайты грузятся (включая `.jpg`); рендер без ошибок.

## [Графика: анимация, земля, спрайты платформ]

### Анимация персонажа (2 кадра)
- Добавлен второй спрайт персонажа «в прыжке»: файл `assets/images/player_jump.png`
  (константа `IMAGE_PLAYER_JUMP`).
- В `GameView` загружаются обе позы (стойка/падение и прыжок) + их отражённые версии.
- `GameView._draw_player` выбирает позу по скорости: если игрок летит вверх
  (`vy < 0`) — поза прыжка, иначе — обычная. При движении влево спрайт отражается.

### Земля на старте, небо выше
- Добавлен фон-небо (`background.png`, тайл) и **земля** (`ground.png`, константа
  `IMAGE_GROUND`).
- Земля — это объект, зафиксированный в мире у нижней границы старта
  (`GROUND_TOP_Y`). Метод `GameView._draw_ground` рисует её тайлами по низу.
- При подъёме камера уходит вверх, и земля **сама уезжает вниз за экран** —
  остаётся только небо. Отдельной логики «переключения» не нужно.

### Платформы в стиле Minecraft (спрайты по типам)
- Для каждого типа платформы свой PNG:
  - `platform_static.png`, `platform_moving.png`, `platform_breakable.png`,
    `platform_spring.png` (константы `IMAGE_PLATFORM_*`).
- `GameView` хранит словарь `kind → спрайт` и рисует нужный спрайт вместо цветного
  прямоугольника. Если файла нет — показывается плейсхолдер (игра не падает).

### Технические детали
- Все картинки масштабируются «по-пиксельному» (`smooth=False`) — чёткий пиксель-арт.
- Затронутые файлы: `src/config/constants.py`, `src/views/game_view.py`,
  `docs/ASSETS.md`.
- Проверки: 14 unittest проходят; headless-рендер без ошибок; смена поз
  (прыжок/падение) подтверждена тестовым прогоном.
